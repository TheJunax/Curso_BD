01

Fundamentos y PostgreSQL

Completado

La base son los datos; el SGBD es el software que los gestiona; psql es solo la puerta de entrada.

Conceptos clave

  • Base de datos: colección organizada de datos (curso_bd).
  • SGBD: software que la administra (PostgreSQL).
  • Cliente: psql o pgAdmin.
  • Tabla: filas y columnas; cada columna tiene tipo y dominio.
  • NULL: ausencia de valor; no es 0 ni ''.
  • SQL es declarativo: dices qué quieres, no cómo recorrerlo.

Ojo con

  • NULL = NULL no da verdadero → usar IS NULL.
  • COUNT(*) cuenta filas; COUNT(columna) ignora NULL.
  • Entrar sin cargar env.sh → intenta el puerto 5432 y falla.
-- dentro de psql
\dt                 -- lista las tablas
\d estudiantes      -- describe columnas, tipos y restricciones
\q                  -- salir

SELECT nombre, ciudad
FROM estudiantes
ORDER BY nombre
LIMIT 5;
02

Modelo relacional y claves

Completado

El vocabulario formal y las reglas que impiden datos huérfanos o duplicados.

Conceptos clave

  • relación = tabla · tupla = fila · atributo = columna · dominio = tipo.
  • Superclave ⊇ candidata ⊇ primaria. Alterna = candidata no elegida.
  • Compuesta: dos o más columnas, ej. (id_pedido, id_producto).
  • Foránea: apunta a la PK de otra tabla; garantiza integridad referencial.
  • Integridad: de entidad (PK no nula), referencial (FK válida), de dominio (tipo/CHECK).
  • ON DELETE: CASCADE borra hijos · RESTRICT bloquea · SET NULL deja la FK nula.

Ojo con

  • Confundir CASCADE con SET NULL: uno borra, el otro conserva.
  • FK sin índice → borrados y joins lentos.
  • Una FK debe apuntar a PK o a una columna UNIQUE.
\d detalle_pedido

-- PK compuesta + dos FK
PRIMARY KEY (id_pedido, id_producto)
REFERENCES pedidos(id)   ON DELETE CASCADE
REFERENCES productos(id) ON DELETE RESTRICT
03

Álgebra relacional

Completado

El "por qué" del SQL: cada operación del álgebra tiene su cláusula.

Conceptos clave

  • σ (selección) → WHERE.
  • π (proyección) → columnas del SELECT (el FROM no es ninguna).
  • ∪ ∩ − → UNION / INTERSECT / EXCEPT.
  • UNION elimina duplicados (conjuntos); UNION ALL los conserva (bolsas).
  • × → CROSS JOIN; θ-join → JOIN ... ON = σ(×).
  • JOIN combina horizontal; UNION apila vertical.

Ojo con

  • JOIN sin ON es error de sintaxis; el producto es CROSS JOIN.
  • Emparejar por id = id en vez de FK ↔ PK: no falla, pero miente.
  • Regla de oro: el join se hace por FK ↔ PK.
-- estudiantes con sus cursos y nota
SELECT e.nombre, c.nombre, m.nota
FROM estudiantes e
JOIN matriculas m ON m.id_estudiante = e.id
JOIN cursos c     ON c.id = m.id_curso
WHERE m.nota >= 4;

04

Modelado Entidad-Relación (ER/EER)

Completado

El plano antes de construir: entidades, atributos, relaciones y reglas de participación.

Conceptos clave

  • Entidad fuerte tiene identidad propia; débil depende de otra (clave parcial).
  • Atributos: simple, compuesto, multivaluado, derivado.
  • Cardinalidad por lado: cada extremo lleva un solo símbolo, 1 o N.
  • Participación: total si toda instancia debe participar; parcial si puede no hacerlo.
  • N:M → rombo con N/N; si tiene atributos propios, van en el rombo.
  • Multivaluado → tabla aparte; derivado → se calcula, no se guarda.

Ojo con

  • Matrícula y prerrequisito son relaciones N:M, no entidades.
  • "Estudiante con varios cursos" no es multivaluado: CURSO es entidad.
  • "1:1 por lado" no existe: cada lado lleva 1 o N.
  • Participación: FK NOT NULL ↔ total; nullable ↔ parcial.
  • El modelo manda sobre la foto de datos del momento.

El modelo completo de universidad está más abajo, en ER universidad.

05

Mapeo ER → modelo relacional

Siguiente

Cada figura del diagrama tiene una traducción mecánica a tablas. Aquí el ER se vuelve DDL.

Reglas de traducción

  • Entidad → tabla con su PK.
  • 1:N → FK en el lado N.
  • N:M → tabla puente (PK compuesta, o id + UNIQUE).
  • 1:1 → FK + UNIQUE (o fusionar las tablas).
  • Multivaluado → tabla aparte.
  • Débil → PK compuesta (dueño + clave parcial).
  • Jerarquía → tabla única con discriminador o tablas separadas.

Ojo con

  • Poner la FK en el lado equivocado de un 1:N.
  • Olvidar el UNIQUE en un 1:1 (se vuelve 1:N sin querer).
  • Crear tabla puente sin PK: se permiten duplicados.
  • La tabla puente es consecuencia del N:M, no una entidad nueva.
-- N:M estudiante ↔ curso, con atributos
CREATE TABLE matriculas (
  id_estudiante INT REFERENCES estudiantes(id),
  id_curso      INT REFERENCES cursos(id),
  semestre      VARCHAR(10) NOT NULL,
  nota          NUMERIC(3,1),
  PRIMARY KEY (id_estudiante, id_curso, semestre)
);
06

Normalización (1FN → BCNF)

Pendiente

Quitar redundancia para que una sola verdad no se pueda contradecir.

Conceptos clave

  • Dependencia funcional: X → Y (X determina Y).
  • 1FN: valores atómicos, sin listas en una celda.
  • 2FN: sin dependencias parciales de una clave compuesta.
  • 3FN: sin dependencias transitivas (no clave → no clave).
  • BCNF: todo determinante es superclave.
  • Anomalías: de inserción, actualización y borrado.

Ojo con

  • Normalizar de menos: ciudad repetida en cada pedido.
  • Normalizar de más: joins innecesarios por miedo a repetir.
  • Un precio histórico congelado no es redundancia: es dato de negocio.

07

DDL — definir el esquema

Pendiente

Construir tablas con reglas que la base haga cumplir solita.

Conceptos clave

  • Tipos: INT, GENERATED AS IDENTITY, VARCHAR/TEXT, NUMERIC, DATE, TIMESTAMP, BOOLEAN.
  • Restricciones: PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, CHECK, DEFAULT.
  • ALTER TABLE y DROP TABLE.
  • ON DELETE CASCADE vs RESTRICT.

Ojo con

  • Dinero en FLOAT: siempre NUMERIC.
  • VARCHAR(n) más corto de lo necesario → error de longitud.
  • SERIAL vs GENERATED ... AS IDENTITY (preferir identity).
CREATE TABLE cursos (
  id          INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  codigo      VARCHAR(12) NOT NULL UNIQUE,
  nombre      VARCHAR(120) NOT NULL,
  creditos    SMALLINT NOT NULL CHECK (creditos BETWEEN 1 AND 10),
  id_profesor INT REFERENCES profesores(id) ON DELETE SET NULL
);
08

DML — mover datos

Pendiente

Insertar, actualizar y borrar sin romper la integridad.

Conceptos clave

  • INSERT ... RETURNING para ver lo insertado.
  • UPDATE ... WHERE y DELETE ... WHERE.
  • Cada sentencia es una transacción implícita.
  • La FK se respeta: no puedes insertar un hijo sin padre.

Ojo con

  • UPDATE/DELETE sin WHERE: se va todo.
  • Probar el WHERE con un SELECT antes de borrar.
UPDATE estudiantes
SET ciudad = 'Sincelejo'
WHERE id = 7
RETURNING id, nombre, ciudad;
09

Consultas básicas

Pendiente

Filtrar, ordenar, paginar y manejar NULL sin sorpresas.

Conceptos clave

  • WHERE, ORDER BY, LIMIT/OFFSET, DISTINCT.
  • Operadores: =, <>, >, <, BETWEEN, LIKE, IN.
  • IS NULL, IS NOT NULL, COALESCE.

Ojo con

  • Comillas simples para valores; dobles para identificadores.
  • NULL no se compara con =.
  • NOT IN con NULL puede devolver vacío.
SELECT nombre, COALESCE(ciudad, 'sin dato') AS ciudad
FROM estudiantes
WHERE fecha_nacimiento BETWEEN '2000-01-01' AND '2005-12-31'
ORDER BY nombre
LIMIT 10 OFFSET 0;
10

JOINs

Pendiente

Combinar tablas por su clave, no por coincidencias de números.

Conceptos clave

  • INNER JOIN, LEFT, RIGHT, FULL, CROSS, SELF JOIN.
  • Filtrar en ON vs en WHERE cambia el resultado en los outer joins.
  • Un LEFT JOIN conserva las filas sin pareja (con NULL).

Ojo con

  • JOIN sin condición → producto cartesiano gigante.
  • Filtro del lado derecho en WHERE convierte el LEFT en INNER.
  • Emparejar FK con PK, nunca id = id.
-- todos los cursos, tengan o no profesor
SELECT c.nombre AS curso, p.nombre AS profesor
FROM cursos c
LEFT JOIN profesores p ON p.id = c.id_profesor
ORDER BY curso;
11

Agregación

Pendiente

Resumir muchas filas en grupos con totales y promedios.

Conceptos clave

  • COUNT, SUM, AVG, MIN, MAX.
  • GROUP BY y HAVING (filtra grupos, no filas).
  • COUNT(*) vs COUNT(columna).
  • Se puede agrupar por varias columnas.

Ojo con

  • GROUP BY incompleto: columnas sin agrupar ni agregar.
  • WHERE no filtra agregados; para eso es HAVING.
  • AVG ignora NULL (el promedio puede sorprender).
SELECT c.nombre AS curso,
       COUNT(*) AS inscritos,
       ROUND(AVG(m.nota), 2) AS promedio
FROM matriculas m
JOIN cursos c ON c.id = m.id_curso
GROUP BY c.id, c.nombre
HAVING COUNT(*) >= 3
ORDER BY promedio DESC;
12

Subconsultas y CTEs

Pendiente

Consultas dentro de consultas y nombres reutilizables con WITH.

Conceptos clave

  • Subconsulta escalar (devuelve un valor).
  • IN, NOT IN, EXISTS, NOT EXISTS.
  • Subconsultas correlacionadas: dependen de la fila exterior.
  • WITH (CTE) y CTEs múltiples.

Ojo con

  • NOT IN con NULL: si la subconsulta trae NULL, no devuelve nada. Usar NOT EXISTS.
  • Subconsultas correlacionadas lentas si no hay índice.
WITH promedio AS (
  SELECT id_curso, AVG(nota) AS prom
  FROM matriculas
  GROUP BY id_curso
)
SELECT c.nombre, p.prom
FROM cursos c
JOIN promedio p ON p.id_curso = c.id
WHERE p.prom > 4;
13

Vistas, índices y funciones ventana

Pendiente

Guardar consultas, acelerar búsquedas y numerar filas sin perder el detalle.

Conceptos clave

  • CREATE VIEW y vistas materializadas.
  • Índices B-tree: cuándo sí y cuándo no.
  • EXPLAIN y EXPLAIN ANALYZE.
  • ROW_NUMBER, RANK, DENSE_RANK.
  • OVER (PARTITION BY ... ORDER BY ...).

Ojo con

  • Índices en columnas de baja selectividad (casi no sirven).
  • Cada índice encarece los INSERT/UPDATE.
  • FK sin índice → joins y borrados lentos.
  • RANK salta números en empates; DENSE_RANK no.
SELECT id_curso, id_estudiante, nota,
       RANK() OVER (PARTITION BY id_curso ORDER BY nota DESC) AS puesto
FROM matriculas;

EXPLAIN ANALYZE
SELECT * FROM matriculas WHERE id_curso = 3;
14

Transacciones y concurrencia

Pendiente

Todo o nada: ACID, aislamiento y bloqueos.

Conceptos clave

  • ACID: atomicidad, consistencia, aislamiento, durabilidad.
  • BEGIN, COMMIT, ROLLBACK, SAVEPOINT.
  • Niveles de aislamiento y anomalías de concurrencia.
  • Bloqueos y deadlocks.

Ojo con

  • Olvidar COMMIT: la transacción queda abierta y bloquea.
  • Transacciones largas: más locks y más riesgo de deadlock.
  • Probar siempre con BEGIN ... ROLLBACK antes de un cambio masivo.
BEGIN;
UPDATE cuentas SET saldo = saldo - 100 WHERE id = 1;
UPDATE cuentas SET saldo = saldo + 100 WHERE id = 2;
COMMIT;  -- o ROLLBACK si algo no cuadra

ER universidad — modelo de referencia

tema 4

El diagrama que cerramos en la sesión 5. Es la base del proyecto final.

Entidades

  • DEPARTAMENTO: id_departamento (PK), nombre (UNIQUE), edificio.
  • PROFESOR: id_profesor (PK), nombre (compuesto), email (UNIQUE).
  • ESTUDIANTE: id_estudiante (PK), nombre (compuesto), email (UNIQUE), fecha_nacimiento, edad (derivado), dirección (compuesto), teléfonos (multivaluado).
  • CURSO: id_curso (PK), codigo (UNIQUE), nombre, creditos.
  • TELÉFONO (débil): número (clave parcial), tipo. PK = (id_estudiante, número).

Relaciones

  • DEPARTAMENTO 1:N PROFESOR — profesor total, departamento parcial.
  • PROFESOR 1:N CURSO — ambos parciales (curso puede no tener profe).
  • ESTUDIANTE N:M CURSO — atributos: semestre, nota, fecha_matricula. Ambos parciales.
  • CURSO N:M CURSO — recursiva de prerrequisitos. Ambos parciales.
  • ESTUDIANTE 1:N TELÉFONO — teléfono con participación total.
[DEPARTAMENTO] ─1──<tiene>──N─ [PROFESOR] ─1──<dicta>──N─ [CURSO]
                                                              │
                                             ┌──N──<se matricula>──M── [ESTUDIANTE] ─1──<tiene>──N─ {TELÉFONO}
                                             │
                                          [CURSO] ─N──<es prerrequisito de>──N─ [CURSO]
Traducción a tablas: 1:N → FK en el lado N · N:M → tabla puente · multivaluado → tabla aparte · débil → PK compuesta. Las tablas matriculas y prerrequisitos existen por el N:M, no porque sean entidades.
