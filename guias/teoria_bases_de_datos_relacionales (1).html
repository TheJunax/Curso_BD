Antes de empezar: el vocabulario

Una base de datos relacional guarda la información en tablas. El libro usa nombres matemáticos para ideas sencillas: relación = tabla; atributo = columna; tupla = fila; dominio = valores permitidos de una columna; esquema = el encabezado (nombres de columnas); instancia = las filas que hay en este momento. Todo el libro responde a una pregunta: ¿cómo diseñar, consultar y razonar sobre estas tablas de forma rigurosa?

Notación necesaria

Conjunto {a,b}; x∈A (pertenece); A⊆B (subconjunto); A∪B, A∩B, A−B; producto cartesiano A×B = todos los pares (a,b); |A| = número de elementos; función f:A→B asigna a cada elemento de A uno de B; ∀ "para todo", ∃ "existe", ∧ "y", ∨ "o", ¬ "no", ⇒ "implica", ⇔ "si y solo si". Como en el libro, un conjunto de atributos se escribe pegado: XY = X∪Y, y U es el conjunto de todos los atributos.

Relaciones y esquemas de relación

En simple

Una base de datos relacional es un conjunto de tablas. Este capítulo les pone nombre exacto a sus partes.

  • Relación: una tabla sin orden y sin filas repetidas.
  • Atributo: el nombre de una columna.
  • Tupla: una fila.
  • Dominio: los valores que puede tener una columna.
  • Clave: lo mínimo que identifica una fila de forma única, como la cédula de una persona.

Formaliza la tabla. Una relación es un conjunto de tuplas: el orden de filas y columnas no importa y no hay filas repetidas. Cada atributo tiene un dominio, y cada tupla asigna un valor de ese dominio a cada atributo.

Ejemplo. Esquema Estudiante(Id, Nombre, Carrera). Una instancia: (1, Ana, Física), (2, Luis, Música).

Una clave es un conjunto mínimo de atributos que identifica de forma única cada fila (aquí, Id). Las actualizaciones (insertar, borrar, modificar) deben respetar esas restricciones: insertar otro estudiante con Id 1 se rechaza.

Paso a paso, con ejemplos

Usaremos una tabla de ejemplo en todo el capítulo: Estudiante(Id, Nombre, Carrera) con las filas (1,Ana,Física), (2,Luis,Música), (3,Eva,Física).

  1. Atributo y dominio. Un atributo es el nombre de una columna (Carrera). Su dominio es el conjunto de valores que esa columna puede tomar. Por ejemplo, dom(Id) = números enteros positivos, dom(Carrera) = {Física, Música, …}.
  2. Tupla. Una fila es una función: recibe el nombre de un atributo y devuelve su valor. Para la primera fila, t(Nombre)=Ana. La notación t[Id,Nombre] significa "quedarse solo con esas dos columnas de t": es (1,Ana).
  3. Relación = conjunto. En matemáticas un conjunto no tiene orden ni repetidos. Por eso: (a) cambiar el orden de las filas o de las columnas no cambia la relación; (b) no puede haber dos filas idénticas; si intentas insertar (1,Ana,Física) otra vez, simplemente no cambia nada.
  4. Esquema vs. instancia. El esquema Estudiante(Id,Nombre,Carrera) es la estructura y casi nunca cambia. La instancia es el contenido de las filas en este momento y cambia constantemente. El libro razona sobre el esquema, para que las conclusiones valgan para cualquier instancia posible.
  5. Probar si algo es clave. Se toma un candidato K y se busca un par de filas distintas con el mismo valor en K. Si existe, K no es superclave.
    • K={Carrera}: Ana y Eva tienen Carrera=Física y son filas distintas, así que no es clave.
    • K={Id}: no hay dos Ids iguales, así que es superclave. Es clave si además ningún subconjunto propio lo es: el único subconjunto propio (no vacío) es el vacío, que no identifica nada, así que {Id} es clave.
    • K={Id,Nombre}: también identifica filas (superclave), pero no es clave porque su subconjunto {Id} ya basta.
    • K={Nombre}: hoy funciona (Ana, Luis, Eva son distintos), pero mañana puede entrar otra Ana. Una clave es una regla del mundo real que debe cumplirse siempre, no un accidente de los datos de hoy.
  6. Actualizaciones y claves. Insertar (4,Ana,Música): válido (Id nuevo). Insertar (1,Pablo,Arte): se rechaza, porque repite el Id 1 con otra fila. Modificar el Id de Luis a 3: se rechaza por lo mismo. Borrar una fila: siempre es válido respecto a la clave.
Matemática formal

Esquema: R={A₁,…,Aₙ}, cada Aᵢ con dominio Dᵢ. Tupla: función t que a cada Aᵢ le asigna t(Aᵢ)∈Dᵢ. Relación: conjunto finito r ⊆ D₁×…×Dₙ; por ser conjunto, |r| ≤ |D₁|·…·|Dₙ|. Para X⊆R, t[X] es la restricción de t a X.

Superclave: K⊆R tal que ∀t₁,t₂∈r: t₁[K]=t₂[K] ⇒ t₁=t₂. Clave: superclave tal que ningún subconjunto propio lo es. Insertar t es válido solo si r∪{t} sigue cumpliendo la condición.

Ver respuesta

Operadores relacionales

En simple

Son las operaciones con que se consultan las tablas: cada una recibe tablas y devuelve otra tabla.

  • Selección σ: quedarse con algunas filas.
  • Proyección π: quedarse con algunas columnas.
  • Unión, intersección, diferencia: juntar, coincidir o restar filas de dos tablas iguales en forma.
  • Join ⋈: pegar filas de dos tablas que comparten un valor, como unir alumnos con sus inscripciones por el Id.

Son las "operaciones aritméticas" de las tablas: toman relaciones y devuelven una relación.

Booleanos: unión (filas de una u otra), intersección (filas en ambas), diferencia (en una pero no en la otra); exigen el mismo esquema. Selección σ: filtra filas que cumplen una condición. Proyección π: conserva solo algunas columnas y elimina duplicados. Join natural ⋈: une filas de dos tablas que coinciden en sus atributos comunes.

Ejemplo. Vuelo(Nro, Origen) ⋈ Piloto(Nombre, Nro) empareja cada vuelo con sus pilotos usando Nro. Si no hay atributos comunes, el join es el producto cartesiano (todas las combinaciones). El join es conmutativo y asociativo; las filas sin pareja "desaparecen" (filas colgantes).
Paso a paso, con ejemplos

Además de Est(Id,Nombre,Carrera) del capítulo 1, tenemos Insc(Id,Curso) = (1,BD), (1,Álgebra), (2,BD), (3,Álgebra).

  1. Selección. Se recorre cada fila y se conserva solo si cumple la condición. σ_{Carrera='Física'}(Est): Ana ✓, Luis ✗, Eva ✓ → {(1,Ana,Física),(3,Eva,Física)}. El esquema no cambia; solo se pierden filas.
  2. Proyección. Se descartan columnas y después se eliminan los duplicados (porque el resultado debe ser un conjunto). π_Carrera(Est): primero salen Física, Música, Física; sin repetidos: {Física, Música}. El esquema se reduce; las filas pueden disminuir.
  3. Unión, intersección y diferencia. Solo tienen sentido si ambas tablas tienen las mismas columnas. Sean a={1,2,3} y b={3,4} (Ids): a∪b={1,2,3,4}, a∩b={3}, a−b={1,2}, b−a={4} (la diferencia no es simétrica).
  4. Join natural, calculado lentamente. Est⋈Insc. (a) Atributos comunes: solo Id. (b) Para cada fila de Est buscamos las de Insc con el mismo Id: Ana(1) ↔ (1,BD) y (1,Álgebra); Luis(2) ↔ (2,BD); Eva(3) ↔ (3,Álgebra). (c) Cada pareja se fusiona escribiendo el Id una sola vez. Resultado, 4 filas con esquema (Id,Nombre,Carrera,Curso): (1,Ana,Física,BD), (1,Ana,Física,Álgebra), (2,Luis,Música,BD), (3,Eva,Física,Álgebra).
  5. Filas colgantes. Si agregamos (4,Pablo,Arte) a Est y Pablo no tiene inscripciones, desaparece del join. Por eso π_{Id,Nombre,Carrera}(Est⋈Insc) es un subconjunto de Est (sin Pablo): nunca tiene más filas, a veces menos.
  6. Sin atributos comunes. Si dos tablas no comparten columnas, toda fila de una es compatible con toda fila de la otra: el join es el producto cartesiano. Con 3 filas y 2 filas salen 3·2=6.
  7. Por qué la propiedad final importa. Si partimos r(A,B,C) en π_AB(r) y π_BC(r) y las volvemos a unir, siempre recuperamos al menos las filas originales (r⊆π_AB(r)⋈π_BC(r)), pero puede aparecer alguna más (filas "espurias"). Evitarlo es el objetivo de la descomposición sin pérdida (caps. 6–9).
Matemática formal

Sean r(R), s(S). Booleanos (R=S): r∪s={t | t∈r ∨ t∈s}, r∩s, r−s={t∈r | t∉s}. Selección: σ_C(r)={t∈r | C(t)}. Proyección: π_X(r)={t[X] | t∈r}. Join natural:

r⋈s = {t sobre R∪S | t[R]∈r ∧ t[S]∈s}

Ejemplo. r(A,B)={(1,2),(3,4)}, s(B,C)={(2,5),(2,6),(7,8)}. Entonces r⋈s={(1,2,5),(1,2,6)}: (3,4) y (7,8) no tienen pareja.

Propiedades (se demuestran con la definición): r⋈s=s⋈r; (r⋈s)⋈u=r⋈(s⋈u); r⋈r=r; si R∩S=∅, r⋈s=r×s y |r⋈s|=|r|·|s|; si R=S, r⋈s=r∩s; π_R(r⋈s)⊆r; si atr(C)⊆R, σ_C(r⋈s)=σ_C(r)⋈s. Clave para los capítulos 6–9: si R₁∪R₂=U, siempre r ⊆ π_R₁(r)⋈π_R₂(r), pero la igualdad puede fallar.

Más operaciones sobre relaciones

En simple

Más herramientas para consultas complejas; todas devuelven siempre una tabla.

  • División: "los que cumplen con todos".
  • Renombrar: cambiar el nombre de una columna.
  • Theta-join: join que compara con < o > en vez de solo igualdad.
  • Álgebra relacional: combinar operadores para formar consultas.
  • Split y factor: partir una tabla en dos / ahorrar espacio.

Amplía el repertorio. División: responde preguntas "para todos" (¿qué estudiantes cursaron todas las materias de la lista?). Relaciones constantes: tablas fijas escritas en la consulta. Renombrar atributos: permite unir una tabla consigo misma. Equijoin: join por igualdad entre columnas con distinto nombre. Theta-join: join con cualquier comparación (<, >, ≠).

Un conjunto de operadores combinados forma una expresión del álgebra relacional, que funciona como una función de relaciones de entrada a una de salida. Basta un subconjunto pequeño (σ, π, ⋈, ∪, −) para expresar casi todo; el capítulo también presenta split y factor, operadores que descomponen una relación en partes.

Paso a paso, con ejemplos
  1. División: "los que cumplen para todo". Pregunta: ¿qué estudiantes están inscritos en todos los cursos de s={BD,Álgebra}? Calculamos Insc÷s con la fórmula π_Id(Insc) − π_Id((π_Id(Insc)×s) − Insc):
    • π_Id(Insc)={1,2,3}.
    • Producto con s: todas las parejas posibles (Id,Curso): (1,BD),(1,Álgebra),(2,BD),(2,Álgebra),(3,BD),(3,Álgebra).
    • Restamos Insc: quedan las parejas que faltan: (2,Álgebra) y (3,BD).
    • Proyectamos a Id: {2,3} = estudiantes a los que les falta algún curso.
    • Restamos de {1,2,3}: queda {1}. Solo Ana cursa todos.
  2. Renombrar. Dada Padre(Hijo,Papa), para hallar abuelos hay que unir la tabla consigo misma, pero los nombres coinciden. Renombramos una copia: δ_{Hijo→Papa, Papa→Abuelo}(Padre) y luego Padre⋈ esa copia: unen filas donde el Papa de una es el hijo de la otra.
  3. Theta-join. Emp(Nombre,Sueldo) [Sueldo<Tope] Rango(Cat,Tope) empareja cada empleado con las categorías cuyo tope supera su sueldo. Se calcula como producto cartesiano y luego un filtro con <. Si θ es =, es un equijoin.
  4. Expresión algebraica = función. E(r,s)=π_Nombre(σ_Carrera='Física'(r)⋈s) toma dos tablas y devuelve una. El Teorema 3.1 dice que podemos reescribir cualquier E usando solo operadores sencillos; por ejemplo, el theta-join se reemplaza por producto + selección, y la intersección por r−(r−s).
  5. Split y factor. Split parte una tabla en dos (las filas que cumplen un predicado P y las que no). Factor ahorra espacio: en una lista de pasajeros (Pasajero,Clase,Fumador) hay solo 4 combinaciones de (Clase,Fumador), así que se guarda (Pasajero,Código) y una tabla (Código,Clase,Fumador); al hacer join se recupera la lista original con una columna extra (el código).
Matemática formal

División (S⊂R, T=R−S): r÷s = {t sobre T | ∀u∈s: (t,u)∈r} = π_T(r) − π_T((π_T(r)×s) − r), es decir, se puede definir con operadores básicos. Renombrar: δ_{A→B}(r) cambia el nombre del atributo. Theta-join: r[AθB]s = σ_{AθB}(r×s) con θ∈{=,≠,<,≤,>,≥}; el equijoin es θ de igualdad.

Expresión algebraica: E es una función E: Rel(R₁)×…×Rel(R_q) → Rel(R). Teorema 3.1: toda expresión equivale a otra que usa solo selección con una comparación, join natural, proyección, unión, diferencia, renombre y constantes de un atributo y una tupla (la intersección es r∩s=r−(r−s)). Split: SPLIT_P(r)=(s,s′) con s={t∈r | P(t)} y s′=r−s; P solo puede mirar a t, no a otras tuplas. Factor: separa una relación en dos que, al hacer join, reconstruyen la original con una columna añadida.

Lenguajes de consulta relacionales

En simple

Cómo se ve la teoría en lenguajes reales.

  • SQL: el más usado hoy.
  • QUEL: el lenguaje de INGRES, con variables de fila.
  • QBE: consultas rellenando tablas en pantalla.
  • ISBL: casi álgebra pura.
  • PIQUE: otro lenguaje que el libro describe.

Aterriza la teoría en lenguajes reales: ISBL (casi álgebra pura), QUEL (el de INGRES), SQL, QBE (consultas rellenando tablas en pantalla) y PIQUE. Cada uno se relaciona con el álgebra de los capítulos 2 y 3; el cálculo relacional que inspira a QUEL y QBE lo verás más adelante, en el capítulo 10.

Ejemplo. En SQL: SELECT Nombre FROM Estudiante WHERE Carrera = 'Física', equivalente en álgebra a πNombre(σCarrera='Física'(Estudiante)).
Matemática formal

Cada lenguaje se reduce a álgebra o cálculo. SQL: SELECT A FROM R,S WHERE R.B=S.B AND C equivale a π_A(σ_C(R⋈S)) (el bloque SELECT-FROM-WHERE es una consulta conjuntiva, más negaciones con NOT EXISTS ≈ diferencia). QUEL: RANGE OF e IS Est; RETRIEVE (e.Nombre) WHERE e.Carrera='Física' usa una variable de tupla e, como el cálculo de tuplas. QBE usa variables de dominio (cálculo de dominios), y ISBL es álgebra casi pura. Más adelante (cap. 10) verás el teorema de Codd, que explica por qué todos expresan al menos el álgebra relacional.

Dependencias funcionales (FD)

En simple

Reglas del tipo "si conozco X, conozco Y".

  • Dependencia funcional X→Y: dos filas con el mismo X siempre tienen el mismo Y.
  • Axiomas de Armstrong: tres reglas básicas para deducir nuevas dependencias.
  • Cierre de X: todo lo que X permite conocer.
  • Completos: no se escapa ninguna conclusión cierta.

Una FD X → Y dice: si dos filas tienen el mismo valor en X, tienen el mismo valor en Y. Captura reglas del mundo real: Id → Nombre (un Id corresponde a un solo nombre). Una clave es un caso especial: determina todos los atributos.

Dado un conjunto F de FDs, otras se deducen automáticamente con los axiomas de Armstrong: reflexividad (XY → X), aumentación (si X→Y, entonces XZ→YZ) y transitividad (si X→Y y Y→Z, entonces X→Z). Son correctos (solo deducen verdades) y completos (deducen todas las verdades). Se estudia el cierre F⁺, derivaciones como secuencias y grafos (DAG), y un algoritmo eficiente para probar si una FD se sigue de F, calculando el cierre de X.

Ejemplo cotidiano. En una cédula, el número determina el nombre (cédula → nombre), pero el nombre no determina la cédula: puede haber dos personas con el mismo nombre.
Paso a paso, con ejemplos
  1. Intuición. X→Y significa "conociendo X, el valor de Y queda determinado". En Est, Id→Nombre es verdadera (un Id, un nombre). Carrera→Id es falsa: Ana y Eva tienen la misma Carrera pero distinto Id.
  2. Cómo se comprueba. Se buscan dos filas con el mismo valor en X. Si todas esas parejas coinciden en Y, la FD se cumple; basta una pareja que no coincida para refutarla. Importante: una FD es una regla de diseño, no una conclusión de los datos de hoy.
  3. Deducir nuevas FDs. Dado F={A→B, B→C}. Por transitividad (F3): si A determina B y B determina C, entonces A→C. Por aumentación (F2) con D: AD→BD. Por reflexividad (F1): AB→A siempre es cierta (no aporta información, es "trivial").
  4. Cierre de atributos, despacio. Sea U=ABCDE y F={A→B, BC→D, D→E}. Calculemos (AC)⁺:
    • Empezamos con Z={A,C}.
    • A→B: A está en Z, agregamos B: Z={A,B,C}.
    • BC→D: B y C están en Z, agregamos D: Z={A,B,C,D}.
    • D→E: D está en Z, agregamos E: Z={A,B,C,D,E}.
    • Ya no hay nada que agregar. (AC)⁺=U, luego AC determina todo: es superclave (y clave, pues A⁺={A,B} y C⁺={C} no bastan).
  5. Probar una FD con el cierre. ¿Se sigue AC→E? Sí, porque E∈(AC)⁺. ¿Y A→E? A⁺={A,B}, no contiene E: no se sigue.
  6. Por qué los axiomas son completos (idea). Si A→E no se sigue, construimos una relación de dos filas que lo demuestra: una fila con todo 1 y otra con 1 en los atributos de A⁺={A,B} y 0 en los demás: (1,1,1,1,1) y (1,1,0,0,0). Esta relación cumple F (se revisa cada FD) pero viola A→E: las filas coinciden en A y difieren en E. Así, lo que no se deriva no es cierto en general.
Matemática formal

Definición. r satisface X→Y si ∀t₁,t₂∈r: t₁[X]=t₂[X] ⇒ t₁[Y]=t₂[Y]. F⊨f ("F implica f") si toda relación que satisface F satisface f. Cierre: F⁺={f | F⊨f}.

Axiomas de Armstrong: (F1) reflexividad: Y⊆X ⇒ X→Y; (F2) aumentación: X→Y ⇒ XZ→YZ; (F3) transitividad: X→Y ∧ Y→Z ⇒ X→Z. Reglas derivadas: unión (X→Y, X→Z ⇒ X→YZ), descomposición (X→YZ ⇒ X→Y), pseudotransitividad (X→Y, WY→Z ⇒ XW→Z).

Prueba de la unión: de X→Y por F2 con X: X→XY; de X→Z por F2 con Y: XY→YZ; por F3: X→YZ.

Correctos y completos: F⊢f ⇔ F⊨f. Correctos: se verifica cada axioma con la definición. Completitud: si X→Y no es derivable, la relación de dos tuplas que coinciden exactamente en X⁺ cumple F y viola X→Y.

Cierre de atributos: X⁺={A | F⊢X→A}; X→Y∈F⁺ ⇔ Y⊆X⁺. Algoritmo: Z:=X; mientras exista V→W∈F con V⊆Z y W⊄Z, hacer Z:=Z∪W. Ejemplo: F={A→B, B→C}: {A}→{A,B}→{A,B,C}, luego A→C∈F⁺. Cada pasada recorre F a lo sumo |F| veces, así que es polinomial (con estructuras adecuadas, lineal).

Covers (cubiertas) de dependencias funcionales

En simple

Una misma lista de reglas se puede escribir de muchas formas; aquí se busca la más corta.

  • Cover: otra lista de reglas que dice exactamente lo mismo.
  • Redundante: una regla que ya se deduce de las demás.
  • Atributo extraño: un dato que sobra dentro de una regla.
  • Mínimo: el menor número de reglas posible.

Dos conjuntos de FDs son equivalentes (cada uno es un cover del otro) si implican exactamente lo mismo. ¿Por qué importa? Porque conviene representar las reglas de la forma más corta posible. Se definen versiones cada vez más depuradas: no redundante (ninguna FD sobra), sin atributos extraños (nada sobra dentro de una FD), canónico, mínimo (menos FDs posibles) y óptimo (menor tamaño total). El capítulo da algoritmos para calcularlos y presenta los covers anulares y las FDs compuestas.

Matemática formal, explicada despacio

Repaso: F⁺ son todas las dependencias que se deducen de F, y X⁺ es el cierre de X (capítulo 4). Con esas dos herramientas se limpian las listas de reglas.

Equivalencia: F ≡ G

En palabras: dos listas dicen lo mismo si cada regla de una se deduce de la otra.

Cómo se comprueba: (1) para cada X→Y de F, calcula X⁺ usando G y mira si contiene Y; (2) repite al revés.

Ejemplo: F={A→B, B→C, A→C} y G={A→B, B→C}. Con G, A⁺={A,B,C} contiene C, así que A→C se deduce de G; las otras dos ya están en G. Al revés es inmediato (G⊆F). Son equivalentes.

Regla redundante

En palabras: una regla que sobra porque las demás ya la implican.

Cómo se comprueba: quita X→Y, calcula X⁺ con las que quedan; si contiene Y, era redundante. En el ejemplo anterior, A→C es redundante.

Atributo extraño

En palabras: una columna del lado izquierdo de una regla que no hace falta, porque las otras ya la determinan.

Condición: A es extraño en X→Y si Y ⊆ (X−A)⁺ (el cierre se calcula con todo F).

Ejemplo: F={AB→C, A→B}. ¿Sobra B en AB→C? Calculamos (AB−B)⁺=A⁺={A,B,C}, que contiene C. Sí sobra: AB→C pasa a A→C. El conjunto {A→C, A→B} es equivalente al original.

Cover canónico, mínimo y óptimo

Receta para el canónico: (1) separar los lados derechos (X→YZ se vuelve X→Y y X→Z); (2) quitar atributos extraños; (3) quitar reglas redundantes. El orden importa: primero extraños, luego redundantes.

Mínimo: tiene el menor número de reglas. Óptimo: tiene el menor número total de letras. Pueden ser listas distintas.

Equivalencia de lados izquierdos: X↔Y significa X→Y y Y→X (se determinan mutuamente, como Id y Cédula); se tratan como un solo grupo al construir el cover mínimo.

Bases de datos y formas normales

En simple

Cómo repartir los datos en tablas sin repetir información ni perder nada.

  • Anomalía: un problema causado por datos repetidos al insertar, borrar o modificar.
  • Forma normal (1NF, 2NF, 3NF, BCNF): niveles de buen diseño.
  • Sin pérdida: se puede partir una tabla y reconstruirla tal cual.
  • Preservar dependencias: las reglas se siguen pudiendo comprobar.
  • Síntesis: construir las tablas directamente desde las reglas.

Una base de datos suele tener varias tablas (un esquema de base de datos). Un mal diseño causa anomalías: datos repetidos, imposibilidad de insertar un dato sin otro, o pérdida de información al borrar.

Las formas normales son niveles de calidad del diseño: 1NF (valores atómicos), 2NF, 3NF (ningún atributo depende de otro no clave) y BCNF (todo determinante es clave). Dos métodos para lograrlas: descomposición (partir tablas defectuosas, con riesgo de perder FDs) y síntesis (construir tablas directamente desde un cover mínimo, una por grupo de FDs, y garantizar que haya una clave). También trata los atributos evitables y los problemas de BCNF.

Ejemplo cotidiano. Si anotas la ciudad de Ana en cada pedido y Ana se muda, debes corregir muchas filas y puedes olvidar alguna. Eso es una anomalía de modificación, y la normalización la evita.
Matemática formal, explicada despacio

Aquí R={R₁,…,R_p} es la lista de tablas del diseño, y U reúne todas las columnas que aparecen en ellas.

Descomposición sin pérdida

En palabras: partimos una tabla grande en varias y, al unirlas con join, debemos recuperar exactamente la original, ni más ni menos filas.

Ejemplo que funciona. r(A,B,C)={(1,2,3),(4,2,3)} con B→C. π_AB={(1,2),(4,2)}, π_BC={(2,3)}; el join da (1,2,3),(4,2,3). Igual a r ✓.

Ejemplo que falla. Sin B→C: r={(1,2,3),(4,2,5)}. π_AB={(1,2),(4,2)}, π_BC={(2,3),(2,5)}; el join da 4 filas, incluyendo (1,2,5) que no existía.

Criterio para dos tablas: es sin pérdida cuando las columnas que comparten (R₁∩R₂) determinan por completo a una de las dos tablas. En el primer ejemplo, B (lo común) determina C.

Preservar dependencias

En palabras: después de partir, cada regla original debe poder comprobarse mirando una sola tabla.

Ejemplo: U=CSZ (ciudad, calle, zip), F={CS→Z, Z→C}. Si partimos en ZC y SZ, la regla CS→Z necesita C y S juntos, que ya no están en la misma tabla: se pierde.

Formas normales, en cuatro niveles

  • 2NF: un dato que no es parte de una clave no puede depender solo de un pedazo de la clave. Violación: Insc(Id,Curso,NombreCurso) con clave Id+Curso; como Curso→NombreCurso, el nombre depende solo de Curso.
  • 3NF: un dato que no es clave no puede depender de otro dato que tampoco es clave. Violación: Emp(Id,Depto,Jefe) con Id→Depto y Depto→Jefe: Jefe depende de Depto, no de la clave. (Excepción: si el dato determinado es parte de alguna clave, es "primo".)
  • BCNF: todo lo que determina a otra columna debe ser clave. Es más estricto que 3NF.
  • Orden de exigencia: BCNF ⇒ 3NF ⇒ 2NF ⇒ 1NF.

Caso donde 3NF y BCNF difieren: en CSZ con Z→C, C es primo (está en la clave SZ), así que cumple 3NF; pero Z determina a C y Z no es clave, así que no cumple BCNF.

Algoritmo de síntesis, con ejemplo

Pasos: (1) calcula un cover mínimo; (2) por cada lado izquierdo distinto crea una tabla con ese lado más todo lo que determina; (3) si ninguna tabla contiene una clave, agrega una.

Ejemplo: U=ABCD, F={A→B, A→C, B→D}. Grupo A: tabla ABC. Grupo B: tabla BD. Como A⁺=ABCD, A es clave y ya está en ABC. Resultado: {ABC, BD}, en 3NF, sin pérdida y con todas las reglas preservadas.

Dependencias multivaluadas, de join y más formas normales

En simple

Hay repeticiones que "si conozco X, conozco Y" no explica: aparecen cuando dos listas son independientes.

  • Multivaluada X↠Y: para cada X, la lista de Y no depende del resto de columnas.
  • 4NF: diseño sin repeticiones causadas por multivaluadas.
  • Dependencia de join: la tabla es igual al join de ciertas partes suyas.
  • PJNF: el nivel de diseño más alto con estas dependencias.

Las FD no describen todas las redundancias. Una dependencia multivaluada X ↠ Y ocurre cuando, para cada X, los valores de Y son independientes del resto.

Ejemplo. Curso(Materia, Libro, Profesor): los libros de una materia no dependen de quién la enseñe. Resultado: se repiten todas las combinaciones libro×profesor. Solución: dos tablas, (Materia, Libro) y (Materia, Profesor).

El capítulo da axiomas para MVDs, la Cuarta Forma Normal (4NF), las dependencias de join (una tabla es igual al join de sus proyecciones) y la forma normal proyección-join (PJNF), el nivel más alto de redundancia eliminable con estas dependencias.

Matemática formal, explicada despacio

Hay datos repetidos que ninguna dependencia funcional explica. Pasa cuando una tabla guarda dos listas independientes pegadas.

Dependencia multivaluada X ↠ Y

En palabras: para cada valor de X, la lista de valores de Y es independiente del resto de columnas.

Ejemplo. r(Materia,Libro,Prof) tiene (BD,l₁,p₁), (BD,l₁,p₂), (BD,l₂,p₁), (BD,l₂,p₂). Los libros de BD no dependen de quién la dicte, así que se combinan todos con todos.

Prueba con la definición: toma t₁=(BD,l₁,p₁) y t₂=(BD,l₂,p₂) (misma Materia). Intercambia: el Libro de t₁ con el resto de t₂ da (BD,l₁,p₂), que sí existe ✓. Si borramos esa fila, falla y la MVD deja de cumplirse.

Versión con join: X↠Y equivale a r = π_XY(r) ⋈ π_XZ(r), con Z las demás columnas. Es decir, se puede guardar en dos tablas, (Materia,Libro) y (Materia,Prof), sin perder nada.

Axiomas, en palabras

  • Replicación: toda FD X→Y es también X↠Y (un solo valor es una lista de uno).
  • Complementación: si Materia↠Libro, entonces Materia↠Prof: lo que sobra también es independiente.
  • Transitividad: si X↠Y y Y↠Z, entonces X↠Z−Y.
  • Coalescencia: permite concluir una FD a partir de una MVD cuando hay un lado derecho de un solo valor.

Dependencia de join y formas normales

JD *[R₁,…,Rₙ]: la tabla es igual al join de sus proyecciones sobre R₁,…,Rₙ. Una MVD es el caso de dos partes: X↠Y ≡ *[XY, XZ].

JD embebida: solo se cumple sobre algunas columnas, no sobre toda la tabla.

4NF: toda MVD no trivial debe tener como lado izquierdo una clave. (Trivial: Y⊆X o XY=U.) PJNF: toda JD que se cumple es consecuencia de las claves; es el nivel más exigente.

Mapeos proyección-join, tableaux y el chase

En simple

Un método mecánico para comprobar si una conclusión se sigue de unas reglas.

  • Tableau: una tabla de símbolos que representa "una fila cualquiera".
  • Chase: aplicar las reglas una y otra vez hasta que nada cambie.
  • Mapeo de contención: forma de probar que una tabla cabe dentro de otra.
  • Church-Rosser: el orden en que se aplican las reglas no cambia el resultado.

Una herramienta para demostrar cosas automáticamente. Un tableau es una tabla de símbolos (variables) que representa una relación genérica o una consulta. Permite comparar esquemas y expresiones mediante mapeos de contención (comprobar si una tabla "cabe" dentro de otra).

El chase es un algoritmo que parte de un tableau y le aplica reglas (F-rules para FDs, J-rules para JDs) hasta que no cambia más. Gracias a la propiedad Church-Rosser el resultado final no depende del orden. Sirve para probar si un conjunto de dependencias implica otra, y para saber si una descomposición no pierde información.

Ejemplo cotidiano. El chase es como un detective: parte de pistas (las filas), aplica reglas ("mismo B implica mismo C") y deduce hechos nuevos hasta que no puede deducir más.
Matemática formal, explicada despacio

Es una máquina de demostrar: sirve para contestar "¿esta regla se sigue de estas otras?" sin razonar a mano.

Tableau

En palabras: una tabla con letras en vez de valores, que representa "una fila cualquiera". Las a son símbolos distinguidos (valores que queremos seguir) y las b son valores desconocidos.

Ejemplo. R={AB,BC}, U=ABC:
fila 1 = (a₁, a₂, b₁) (la parte AB es conocida)
fila 2 = (b₂, a₂, a₃) (la parte BC es conocida)
Pregunta: ¿puede aparecer la fila toda conocida (a₁,a₂,a₃)? Si sí, no hay pérdida.

El chase: reglas que se aplican hasta que nada cambia

F-regla (para X→A): si dos filas coinciden en X, se igualan en A. Ejemplo: con B→C, ambas filas tienen a₂ en B; entonces b₁ se reemplaza por a₃. La fila 1 queda (a₁,a₂,a₃): toda distinguida, luego la descomposición es sin pérdida.

J-regla (para *[AB,BC]): si dos filas coinciden en B, se agrega una fila con la parte AB de una y la parte BC de la otra. Ejemplo: de (1,2,5) y (7,2,3) sale (1,2,3).

Teorema: las reglas C implican *[R] exactamente cuando el chase produce una fila toda distinguida.

Contención y propiedades

Mapeo de contención: el tableau T₂ "cabe" en T₁ si puedo renombrar los símbolos de T₂ para que sus filas aparezcan en T₁ sin cambiar el resumen. Ejemplo: (a,b₁),(a,b₂) cabe en (a,b₁) con b₂→b₁: basta una fila.

Church-Rosser finito: el chase siempre termina y da el mismo resultado sin importar en qué orden se apliquen las reglas.

Costo: con JDs puede ser muy lento (NP-difícil), con solo FDs es rápido.

Teoría de la representación

En simple

Cuándo un grupo de tablas guarda fielmente la información de una tabla grande.

  • Representación adecuada: se recupera todo y las reglas se pueden comprobar.
  • Pérdida: al unir las partes salen filas que no existían.
  • Equivalencia de datos: dos diseños distintos guardan lo mismo.

Pregunta: si partimos una gran tabla universal en varias tablas, ¿conservamos la información? Define nociones de representación adecuada: que se pueda reconstruir la relación original (sin pérdida), que se preserven las dependencias, que no haya redundancia ni anomalías. También define la equivalencia de datos entre dos esquemas (almacenan lo mismo con distinta forma) y presenta pruebas, basadas en el chase, cuando las restricciones son FDs y MVDs.

Matemática formal, explicada despacio

La pregunta es: si guardo mis datos en varias tablas pequeñas en lugar de una grande, ¿pierdo algo?

Las tres operaciones

Proyectar π_R: parte la tabla grande en sus tablas pequeñas. Unir ⋈_R: hace join de las pequeñas. Ida y vuelta m_R: proyectar y volver a unir. Siempre se cumple que r ⊆ m_R(r): nunca se pierden filas, pero pueden sobrar.

Ejemplo del libro: r={(1,3,5),(1,4,6),(2,4,5),(2,4,6)} con R={AB,BC}. Al unir sale la fila extra (1,4,5) (figura 5): hay pérdida.

Conjuntos de tablas: Q, P, πP, CW y L

  • Q: todas las tablas posibles sobre U. P: las que cumplen las reglas (SAT(C)).
  • πP: las partes que salen de tablas válidas de P.
  • CW (por componente): cada tabla pequeña, por separado, parece válida, aunque juntas no lo sean.
  • L = CW ∩ πQ: las que parecen válidas por separado y además se pueden unir.

Ejemplo propio. P=SAT(A→C), R={AB,BC}, r₁(A,B)={(1,2),(1,3)}, r₂(B,C)={(2,5),(3,6)}. Cada una por separado puede venir de una tabla válida, y al unirlas sale {(1,2,5),(1,3,6)}, que viola A→C. Así, ese par está en L pero no en πP: por eso πP ⊆ L y no al revés.

Representación adecuada y equivalencia de datos

Rissanen (componentes independientes): (1) sin pérdida: m_R(r)=r para toda r en P; (2) las reglas se verifican tabla por tabla (πP = L), sin necesidad de unirlas.

Equivalencia de datos: dos diseños distintos son equivalentes si guardan exactamente la misma información. Con FDs y MVDs se decide con el chase del capítulo 8.

Sistemas de consulta

En simple

Qué tan potente es un lenguaje de consultas. Se comparan varios y resultan equivalentes.

  • Cálculo relacional: describir lo que se quiere con lógica ("existe una fila tal que…").
  • Consulta segura: nunca devuelve infinitos resultados.
  • Teorema de Codd: álgebra y cálculo seguro expresan lo mismo.
  • Consulta conjuntiva: la más común: filtrar, elegir columnas y unir.

¿Cuándo un lenguaje de consultas es "suficientemente potente"? Se comparan varios lenguajes y se demuestra que expresan lo mismo (el resultado clásico de Codd): el álgebra relacional (cómo calcular), el cálculo relacional de tuplas (variables que representan filas) y el cálculo de dominios (variables que representan valores), ambos declarativos (qué se quiere, no cómo). Se introducen las expresiones seguras (que no devuelven infinitos resultados), los tableau queries y las consultas conjuntivas, el núcleo más usado (selección, proyección y join).

Matemática formal

Cálculo de tuplas: {t | φ(t)}, φ construida con átomos R(s), s[A]θu[B], s[A]θc, conectivos ∧ ∨ ¬ y cuantificadores ∃s, ∀s. Ejemplo: π_Nombre(σ_Carrera='Física'(Est)) = {t | ∃s(Est(s) ∧ s[Carrera]='Física' ∧ t[Nombre]=s[Nombre])}.

Cálculo de dominios: {x₁,…,x_k | φ}, con variables que representan valores (Est(x,y,z)). Seguridad: {t | ¬R(t)} es infinita; una expresión es segura si siempre produce valores del dominio activo (los que aparecen en la BD o en la consulta).

Teorema (Codd): álgebra relacional ≡ cálculo de tuplas seguro ≡ cálculo de dominios seguro. Las reducciones traducen: ∧ → join/intersección, ∨ → unión, ¬ → diferencia, ∃ → proyección.

Consultas conjuntivas / tableau: {w | ∃b̄: R(w₁) ∧ … ∧ R(w_k)}; equivalen a álgebra con solo σ(=), π y ⋈, y su valor es T(r) del capítulo 8.

Modificación de consultas

En simple

Reescribir una consulta para que dé el mismo resultado pero más rápido.

  • Optimizar: por ejemplo, filtrar antes de unir.
  • Descomposición: partir una consulta en subconsultas pequeñas.
  • Minimizar un tableau: quitar joins innecesarios.
  • Semijoin: enviar entre computadoras solo las columnas necesarias.
  • Fragmento: un pedazo de tabla guardado en otra máquina.

Una misma consulta puede escribirse de muchas formas, algunas mucho más rápidas. Este capítulo trata de transformarlas sin cambiar su resultado: simplificar y reutilizar subexpresiones, optimizar el álgebra (por ejemplo, filtrar con σ antes del join para manejar menos filas), descomposición de consultas (dividir una consulta en subconsultas más simples, método de INGRES) y minimización de tableaux (eliminar joins innecesarios). Termina con las bases de datos distribuidas: los semijoins reducen los datos que viajan por la red, y los fragmentos dividen las tablas entre máquinas.

Matemática formal

Equivalencias algebraicas (valen para todas las instancias): σ_{C₁∧C₂}(r)=σ_{C₁}(σ_{C₂}(r)); σ_C(r⋈s)=σ_C(r)⋈s si atr(C)⊆R; π_X(r∪s)=π_X(r)∪π_X(s); π_X(σ_C(r))=σ_C(π_X(r)) si atr(C)⊆X. La idea: filtrar antes de unir reduce |r| antes del producto, que cuesta hasta |r|·|s|.

Tableau: T₁≡T₂ ⇔ T₁⊑T₂ y T₂⊑T₁ (contención en ambos sentidos). Minimización: se eliminan filas mientras exista un mapeo de contención hacia la tabla reducida. Ejemplo: T=(a,b₁),(a,b₂) con resumen a; ψ(b₂)=b₁ es contención ⇒ basta una fila. Equivale a π_A(R⋈R)≡π_A(R).

Semijoin: r⋉s=π_R(r⋈s), y r⋈s=(r⋉s)⋈s: en una red se envía solo π_{R∩S}(s), no toda s. Fragmentos: r=r₁∪r₂ (horizontal) o r=π_X(r)⋈π_Y(r) (vertical).

Valores nulos, información parcial y semántica

En simple

Qué hacer cuando falta información en la base de datos.

  • Nulo ⊥: valor desconocido o inexistente.
  • Función de posibilidad: lista de valores reales que el nulo podría tener.
  • Instancia débil: una tabla única que contiene lo que dicen todas las tablas.
  • Función ventana: lo que se puede afirmar sobre un grupo de columnas.
  • Independencia: cada tabla se verifica por separado.

En la realidad faltan datos. Un nulo puede significar "no sé su valor", "no existe" o "no aplica". El capítulo analiza cómo cambian las FDs, las restricciones y los operadores del álgebra cuando hay nulos, mediante funciones de posibilidad (qué valores reales podría tener el nulo).

Luego aborda la semántica: cómo interpretar una base de datos con muchas tablas como si fuera una sola relación universal. Introduce las funciones ventana (window functions), las instancias débiles (weak instances) y el concepto de independencia entre las tablas.

Matemática formal

Relación parcial: tuplas sobre D∪{⊥} (⊥ = nulo). Una función de posibilidad asigna a cada relación parcial r el conjunto POSS(r) de relaciones completas que r podría representar (cada ⊥ se reemplaza por un valor del dominio). Operador generalizado: E(r) se evalúa sobre cada r′∈POSS(r); un resultado es cierto si aparece en todos y posible si aparece en alguno.

FD con nulos: se satisface fuertemente si todas las completaciones la cumplen, y débilmente si alguna la cumple.

Semántica universal. Para d={r₁,…,r_p}, una instancia débil es una relación w sobre U con π_Rᵢ(w)⊇rᵢ para todo i (y que cumple las dependencias C). Una función ventana [X](d) devuelve las X-tuplas que se pueden afirmar sobre d, p. ej. [X](d)=⋂_w π_X(w) sobre las instancias débiles. Independencia: el esquema es independiente si basta que cada rᵢ cumpla localmente las restricciones para que d tenga instancia débil.

Lección 14 · Capítulo 13 del libro

Esquemas de base de datos acíclicos

En simple

Los esquemas sin ciclos se portan especialmente bien.

  • Hipergrafo: dibujo de las tablas como grupos de columnas.
  • Acíclico: sin ciclos.
  • Árbol de joins: las tablas ordenadas en un árbol para unirlas en orden.
  • Reductor completo: secuencia de semijoins que elimina las filas inútiles.
  • Consistencia por pares: cada par de tablas encaja; en acíclicos, entonces todo encaja.

Un esquema puede verse como un hipergrafo (los atributos son nodos; cada tabla, un grupo de nodos). Si no tiene ciclos es acíclico, y entonces ocurren cosas buenas: existe un reductor completo (una secuencia de semijoins que elimina todas las filas inútiles), la JD equivale a un conjunto de MVDs, la descomposición 4NF es única, consistencia por pares implica consistencia total y los joins intermedios no crecen sin control.

Se muestran tres formas equivalentes de reconocerlos: sin ciclos en el hipergrafo (con la reducción de Graham), existencia de un árbol de joins y la propiedad de intersección continua. Se prueba que todas coinciden.

Matemática formal

Hipergrafo H=(U,{R₁,…,Rₙ}). Reducción de Graham: repetir (1) borrar un atributo que aparece en un solo Rᵢ; (2) borrar un Rᵢ contenido en otro Rⱼ. Acíclico ⇔ queda vacío. Árbol de joins: árbol cuyos nodos son los Rᵢ y, para cada atributo A, los Rᵢ que contienen A forman un subárbol conexo. Intersección continua (RIP): existe un orden con ∀i≥2 ∃j.

Ejemplos. {AB,BC,CD}: Graham borra A, D, luego AB→B⊆BC…, queda vacío: acíclico. {AB,BC,CA} (triángulo): ningún atributo está en una sola tabla y ningún Rᵢ está contenido en otro: cíclico. Con r₁={ab,a′b′}, r₂={bc,b′c′}, r₃={ac′,a′c}, el join es vacío aunque cada par join completamente: consistencia por pares ⇏ total si hay ciclos.

Semijoin y reductor completo: programa rᵢ:=rᵢ⋉rⱼ tras el cual π_Rᵢ(⋈d)=rᵢ para todo i. Teorema: para R son equivalentes: (a) acíclico (Graham); (b) tiene árbol de joins; (c) cumple RIP; (d) existe reductor completo; (e) *[R] equivale a un conjunto de MVDs; (f) pairwise ⇒ total; (g) la descomposición 4NF es única.

Lección 15 · Capítulo 14 del libro

Temas variados

En simple

Ampliaciones de la teoría y sus límites.

  • Dependencia de plantilla: regla general: "si existen estas filas, debe existir esta otra".
  • Cierre transitivo: todos los caminos indirectos (A→B→C…); el álgebra no lo calcula.
  • Relación calculada: tabla infinita que se evalúa en lugar de guardarse (como la suma).

Extiende la teoría en cuatro direcciones: (1) lógica y dependencias: las FDs y MVDs pueden verse como fórmulas lógicas; (2) dependencias más generales: de plantilla (template) y FDs generalizadas, con representación gráfica y pruebas de implicación; (3) límites del álgebra relacional: hay consultas que no puede expresar, como el cierre transitivo (todas las conexiones indirectas de un vuelo); (4) relaciones calculadas (por ejemplo, aritmética) que se tratan como tablas infinitas.

Matemática formal

Lógica: X→A equivale a ∀t₁∀t₂ (R(t₁)∧R(t₂)∧t₁[X]=t₂[X] ⇒ t₁[A]=t₂[A]). Para decidir implicación de FDs basta mirar relaciones de dos tuplas, que se leen como interpretaciones de lógica proposicional (el atributo A es "verdadero" si las dos tuplas coinciden en A); con MVDs esta equivalencia deja de valer.

Dependencia de plantilla: (w,{w₁,…,w_k}); r la satisface si ∀ρ: ρ(w₁),…,ρ(w_k)∈r ⇒ ρ(w)∈r. Las JD y MVD son plantillas sin símbolos nuevos. Su implicación se prueba con el chase (cap. 8). Un tipo de FD generalizada permite que el lado derecho dependa de una función de otras columnas. Las clases SAT(C) no siempre son cerradas bajo proyección.

Límite del álgebra: cierre transitivo TC(r)={(a,b) | existe camino de a a b}. Toda expresión tiene un número fijo k de joins, así que solo alcanza caminos de longitud ≤ k: ninguna expresión lo calcula. Relaciones calculadas: p. ej. SUMA(x,y,z) con z=x+y es una "tabla" infinita que se evalúa, no se almacena.

Lección 16 · Énfasis: normalización

La receta de normalización, con ejemplos

Normalizar es repartir los datos en tablas para que cada hecho se guarde una sola vez. No es un truco: es un procedimiento. Sigue siempre esta receta, en este orden:

  1. Reúne datos reales. Escribe 5 o 6 filas de ejemplo; las reglas salen de ahí.
  2. Escribe las dependencias. Por cada par de columnas pregunta: "si conozco X, ¿conozco siempre Y?". Ejemplo: Id → Nombre.
  3. Calcula la clave con cierres: busca el conjunto cuyo cierre sea todas las columnas.
  4. 1NF: cada celda tiene un solo valor (sin listas como "3001, 3002").
  5. 2NF: si la clave tiene varias columnas, ningún dato debe depender de solo una parte.
  6. 3NF/BCNF: ningún dato debe depender de otro dato que no sea clave.
  7. Descompón creando una tabla por cada dependencia problemática y deja la clave en ambas para poder unirlas.
  8. Verifica: el join recupera lo original (sin pérdida) y cada regla vive en alguna tabla (preservación).
  9. 4NF: si hay dos listas independientes en la misma tabla, sepáralas.

Ejemplos de fácil a difícil

Fácil · 1NF. Estudiante(Id, Nombre, Telefonos) con Telefonos = "3001, 3002". Solución: Estudiante(Id, Nombre) y Telefono(Id, Telefono), una fila por teléfono.
Medio · 2NF. Insc(Id, Curso, NombreCurso, Nota), clave (Id, Curso). Como Curso → NombreCurso depende de una parte de la clave, se separa: Curso(Curso, NombreCurso) e Insc(Id, Curso, Nota).
Medio · 3NF. Emp(Id, Depto, Jefe) con Id → Depto y Depto → Jefe. Jefe depende de Depto, que no es clave. Solución: Emp(Id, Depto) y Depto(Depto, Jefe).
Difícil · BCNF. Clase(Estudiante, Curso, Profesor), cada profesor da un solo curso (Profesor → Curso) y (Estudiante, Curso) → Profesor. Está en 3NF pero no en BCNF. Si se parte en (Profesor, Curso) y (Estudiante, Profesor) se pierde (Estudiante, Curso) → Profesor: hay que elegir entre BCNF pura y conservar la regla.
Muy difícil · 4NF. Empleado(Nombre, Hijo, Habilidad) con Nombre ↠ Hijo: 2 hijos × 3 habilidades obligan a 6 filas. Solución: (Nombre, Hijo) y (Nombre, Habilidad): 5 filas en total y sin combinaciones forzadas.

Qué tener en cuenta

  • Sin dependencias escritas no hay normalización: primero las reglas, luego las tablas.
  • Las dependencias vienen del significado de los datos, no de lo que muestran hoy las filas.
  • 3NF casi siempre basta y preserva todas las reglas; BCNF es más estricta pero puede perder alguna.
  • Deja siempre la columna de enlace en ambas tablas (será la clave foránea).
  • Comprueba el "sin pérdida" uniendo y comparando el número de filas.

Un caso completo y cuándo desnormalizar

Caso completo. Una tienda guarda todo en una tabla: Pedidos(IdPedido, Cliente, Ciudad, Producto, Precio) (ver la figura 9). Resolvemos con la receta:

  1. Dependencias: IdPedido → Cliente, Cliente → Ciudad, Producto → Precio.
  2. Clave: (IdPedido, Producto), porque su cierre es todas las columnas.
  3. 2NF: Cliente depende solo de IdPedido y Precio solo de Producto: dependencias parciales.
  4. 3NF: Ciudad depende de Cliente, que no es clave.
  5. Resultado: cuatro tablas; unirlas recupera la original.
CREATE TABLE Cliente(Cliente TEXT PRIMARY KEY, Ciudad TEXT);
CREATE TABLE Producto(Producto TEXT PRIMARY KEY, Precio NUMERIC);
CREATE TABLE Pedido(IdPedido INTEGER PRIMARY KEY,
  Cliente TEXT REFERENCES Cliente(Cliente));
CREATE TABLE Linea(IdPedido INTEGER REFERENCES Pedido(IdPedido),
  Producto TEXT REFERENCES Producto(Producto),
  PRIMARY KEY(IdPedido, Producto));

Cuándo desnormalizar a propósito

  • Solo cuando una consulta medida es lenta y un índice no lo resuelve (módulo 9).
  • Duplica el dato en una sola dirección y documenta quién lo mantiene al día.
  • Para reportes de solo lectura, una tabla plana suele ser aceptable.

Ejercicios (de fácil a difícil)

Ejercicio 8.1. Libro(Isbn, Titulo, Autores) con Autores = "Ana, Luis". ¿Qué forma normal viola? Corrígelo.

Ver respuesta

Ejercicio 8.2. R(A,B,C,D) con F={A→B, B→C, C→D}. Halla la clave y normaliza a 3NF.

Ver respuesta

A⁺=ABCD, la clave es A. B→C y C→D son dependencias entre no claves. Tablas: AB, BC, CD; A queda en AB, que la contiene. Todas las reglas se conservan.

Ejercicio 8.3. R(A,B,C) con F={AB→C, C→B}. ¿3NF? ¿BCNF?

Ver respuesta

Claves: AB y AC (AC⁺=ABC). En C→B, B es primo: 3NF sí. C no es superclave: BCNF no. Partir en CB y AC pierde AB→C.

Ejercicio 8.4. Normaliza Matricula(Id, NombreEst, Curso, NombreCurso, Profesor, OficinaProfesor) con Id→NombreEst, Curso→NombreCurso, Profesor, Profesor→OficinaProfesor.

Lección 18 · Énfasis: índices

Qué es un índice y cómo funciona

Un índice es como el índice de un libro: en vez de leer todas las páginas para encontrar un tema, miras el índice y vas directo. En una base de datos, sin índice el sistema hace un escaneo completo (lee las N filas); con índice B-tree hace unas log N comparaciones.

Con números. Tabla de 1.000.000 de filas. Sin índice: hasta 1.000.000 de lecturas. Con índice B-tree: unas 20 comparaciones (2²⁰≈10⁶).

Tipos de índice

  • B-tree (el estándar): sirve para =, rangos (<, BETWEEN) y ORDER BY.
  • Hash: solo igualdad, un poco más rápido.
  • Único: además impide valores repetidos; la clave primaria crea uno automáticamente.
  • Compuesto: sobre varias columnas; el orden importa.
  • Cubriente: incluye las columnas que la consulta pide, así no se toca la tabla.

El costo de un índice

  • Cada INSERT, UPDATE y DELETE también debe actualizar el índice: más índices, escrituras más lentas.
  • Ocupa espacio en disco y memoria.
  • Un índice en una columna con pocos valores distintos (como Carrera con 3 valores) casi nunca ayuda: no filtra lo suficiente.

Lección 19 · Énfasis: índices

Diseñar índices paso a paso

Receta para indexar:

  1. Encuentra la consulta lenta y mide su tiempo.
  2. Mírala con EXPLAIN: si dice "Seq Scan" o "ALL", recorre toda la tabla.
  3. Elige columnas de WHERE, de JOIN y de ORDER BY, empezando por la más selectiva.
  4. Crea el índice y vuelve a ejecutar EXPLAIN.
  5. Mide otra vez y comprueba que las escrituras no se hayan vuelto un problema.

Ejemplos de fácil a difícil

Fácil. CREATE INDEX idx_est_nombre ON Estudiante(Nombre); acelera WHERE Nombre = 'Ana'.
Fácil · claves foráneas. Indexa la columna que enlaza: CREATE INDEX idx_insc_id ON Inscripcion(Id); acelera el join con Estudiante. Las claves foráneas que salen de normalizar (módulo 8) casi siempre merecen índice.
Medio · compuesto. CREATE INDEX i ON Estudiante(Carrera, Nombre); sirve para WHERE Carrera=… y para Carrera=… AND Nombre=…, pero no para WHERE Nombre=… solo (regla del prefijo izquierdo).
Difícil · cubriente. CREATE INDEX i ON Pedido(Cliente, Fecha) INCLUDE (Total); responde SELECT Fecha, Total … WHERE Cliente=… ORDER BY Fecha leyendo solo el índice y ya ordenado.
Difícil · funciones. WHERE LOWER(Nombre) = 'ana' no usa un índice sobre Nombre. Se crea CREATE INDEX i ON Estudiante(LOWER(Nombre)); o se evita la función.

Errores comunes

  • Indexar todo "por si acaso".
  • Usar funciones o LIKE '%texto' sobre la columna indexada: invalida el índice.
  • Comparar tipos distintos (texto con número).
  • Olvidar el orden de las columnas en el índice compuesto.
